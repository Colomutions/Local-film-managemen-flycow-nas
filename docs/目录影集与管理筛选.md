# 目录影集、分集排序与管理筛选

PC 和 Android 平板管理工作区使用同一组 NAS 接口。标签简介、标签文件及导入规则本次不变。

## 扫描规则

分类绑定目录下，直接包含视频的子目录代表一部作品；只统计该目录直接包含的视频，不把下级作品合并到上层。例如：

```text
av/GDSC/GDSC-24/1.mkv
av/GDSC/GDSC-24/2.mkv     → 一部影集、两个分集
av/ADN/ADN-125/ADN-125.mp4 → 一部单片
av/独立1.mp4
av/独立2.mp4               → 绑定根目录的两个散片各自独立
```

新目录一个视频建单片，多个视频建影集；原单片新增分段后原位升级，保留影片 ID、资料、收藏及播放记录。已有影集只剩一个分段也不降级。旧 `-影集` 标记继续兼容，但新目录无需该标记；旧版嵌套多重影集标记仍报告冲突。

同分类多个来源盘中，相对于分类绑定目录的完整作品路径相同，就属于同一作品；仅最后一级名称相同而上层路径不同的作品分开。目录内不同番号、数字、大小写字母分段均保留在同一部作品中，不依据番号拆组。

手工组成影集后，分集保存的来源盘、相对路径及当前影片归属继续作为扫描依据。新分段进入该来源目录现有分集共同指向的最终影集；连续合并也遵循这一规则，不复活隐藏来源。离线来源仍参与归属判断。同目录已经手工分属多个影片时，扫描保留原归属并报告冲突，新分段不擅自归入任一条目。

旧版逐文件建立的独立条目，在重扫时会按同分类、完整作品目录自动组成影集。例如既有`PPT-123-A.mp4`和`PPT-123-B.mp4`两部单片，重扫后显示为一部影集、两个原分集，原单片从海报墙隐藏。主资料取按文件名自然排序最前分集对应的影片；若该影片只有默认扫描标题，影集标题采用作品目录名，并允许后续 NFO 或采集资料补充正式标题。演员、标签合并去重，任一来源收藏则保留收藏，截图按内容去重，进度和历史跟随原分集迁移。视频不会移动、复制或改名。

只自动归并全部属于该作品目录、且没有显式人工拆分标记的旧独立条目；已有影集与其他影片共同占用目录等歧义仍报告冲突，不擅自改变归属。合并期间正在播放、预览或处理资料任务的目录保留原状并报告冲突，任务结束后可重扫。

自动归并保留主资料的字段来源和人工保护，尚未填写的资料仍可正常补全，已有 NFO 来源仍可按既有规则更新。演员、标签及截图的非空合并结果受保护，避免后续导入丢失并集；原本明确人工清空的字段也保留保护。详情页手工组成影集仍按用户确认的结果保护资料。

schema v37新增扫描归组标记。以后主动拆分的条目保留为人工归属，重扫不会重新合回。升级前未记录拆分意图的旧独立条目，按用户确认的“一作品目录对应一部影片”规则自动归并。PC/平板“影集管理 → 旧数据迁移”仍可用于显式选择主资料后迁移，并与详情页组成影集共用资料合并规则。

## 去掉旧目录后缀

先部署新版 NAS，再把作品目录 `GDSC-24-影集` 改成 `GDSC-24`，最后只重扫对应分类。保持分类绑定目录、来源盘和视频文件名不变。

扫描仅针对明确的旧后缀移除，按同一来源盘、完整相对目录、视频文件名及大小/修改时间作唯一匹配。成功时仅迁移索引路径，保留影片与分集 ID、手工归属、资料、进度和历史；不读完整视频、不做视频哈希、不重复 ffprobe。新旧目录同时存在、候选不唯一或文件属性变更时，扫描报告冲突，不创建猜测的重复条目。

该规则不负责任意移动目录、跨盘搬迁或同时修改视频文件名的重定位。此类改动需另行处理，不能依靠本次后缀迁移自动识别。

## 分集排序

默认按**视频文件名**自然排序：数字按数值比较，忽略前导零和字母大小写，兼容空白、下划线、短横线等分隔符。来源目录和视频扩展名不参与主排序；相同名称使用路径和 ID 稳定排序。

自动模式下，新分段加入名称对应的位置；PC/平板详情的“分集排序”支持拖动或上下移动，保存后切为手动模式。手动模式重扫保持既有顺序，新分段追加末尾；点击“恢复按名称排序”切回自动模式。排序只修改数据库记录，不改文件名或移动视频。

组成影集默认自动排序，只有在预览中调整过分集顺序才保存手动排序。旧版本已有明确 `manual_order` 的影集在 schema v36 升级时保留为手动；其余采用自动。schema v37另行保存人工拆分意图。升级只读取数据库记录并更新旧排序键和归组字段。

排序接口：

```text
PUT /api/v1/admin/collections/{movieId}/episode-order
{"mode":"manual","episodeIds":["完整分集ID列表"]}

PUT /api/v1/admin/collections/{movieId}/episode-order
{"mode":"automatic"}
```

手动保存必须与 NAS 当前完整分集集合一致，否则返回冲突并保持原顺序；接口与扫描串行。`GET /api/v1/movies/{movieId}/episodes` 的 `data.sortMode` 返回当前模式。

## 管理筛选

- 海报墙视图切换左侧“未关联演员”：没有正式演员 ID 关联，且未关联名称恰好为 `AI`（忽略大小写）的标签。只有未匹配演员文字仍会列出；相似标签名不会误排除。与当前分类、搜索及其他筛选组合。
- 演员管理“未关联影片”：按整个 NAS 库统计，没有活动影片关联的演员。离线影片、影集算关联；已合并隐藏的来源条目不算。可与搜索、性别和排序组合，不强制女性。

两种筛选均在 NAS 完整结果上执行，计数和分页保持一致。影片 GET/POST 搜索接受 `missingActors=true`；演员列表接受 `unlinkedOnly=true`，默认都为 false。

## 更新

把本次 NAS 源码同步到现有部署目录，保留原 `.env` 和持久 `data`，在该目录执行：

```sh
sudo -H sh bin/mujing-compose build --pull=false
sudo -H sh bin/mujing-compose up -d --force-recreate
sudo -H sh bin/mujing-compose logs --tail=100 mujing-nas
```

入口沿用 `.env` 选定的单盘/双盘/MDCNG 挂载组合。随后更新 PC 与平板。需要先升级 NAS 才能使用新筛选、排序和安全的去后缀重扫。

若 PC/平板已运行包含组成影集和分集排序入口的调试版，本轮旧条目自动归组只需同步最新 NAS 源码、重新构建并启动，再在分类管理重扫对应分类。仅替换 `data` 不会更新扫描程序；本地尚未提交的新增源码也必须一起同步。

本轮 NAS 静态分析与 Windows 原生编译通过；新增自动归组测试 13 个场景全部通过，覆盖资料、关系、截图及播放记录保留、跨盘、人工拆分保护、播放/任务冲突、空资料补全、已有 NFO 来源继续更新和人工清空保护。schema v37 升级与回滚、分集排序、分类扫描范围、组成影集 API、NFO 批量导入及采集服务回归通过。重复扫描不再写入未变化的影片、分集和关系记录，也不再次探测视频。
