# 内置 WhatsAV 刮削

## 部署

刮削已集成到 `mujing-nas` 镜像。继续使用原有 Compose、媒体挂载和 `/data`，不需要额外的搜刮容器、端口、管理密钥或 MDCNG 部署。

镜像包含 Dart NAS 主程序、Node.js 24、Chromium 和 tini。首次重建会安装 Chromium，镜像体积和运行内存相应增加。Compose 已设置 256 MiB 共享内存和 60 秒退出宽限时间。NAS 非 root 用户及既有媒体只读挂载保持有效。

更新源码后使用现有部署模式重新构建并重建 `mujing-nas` 容器，再更新 Windows 管理端并重新连接 NAS，使客户端读取 `builtinScraping` 能力。继续使用现有 `bin/mujing-compose` 的部署模式；无需运行独立「搜刮」项目的 Compose。本次开发没有部署到真实 NAS。

开发环境可配置 `MUJING_SCRAPER_SCRIPT` 指向本仓库 `scraper/worker.mjs`，`MUJING_SCRAPER_NODE` 指向 Node 可执行文件，`BROWSER_EXECUTABLE` 指向 Chromium/Chrome。镜像已经配置这些默认值。

## Windows 操作入口

- 分类管理顶栏「全库刮削」：处理整个幕境片库；「刮削任务」查看后台任务。
- 分类详情「重新扫描此分类」与「刮削此分类影片」是两个独立按钮。扫描只更新文件索引，不访问 WhatsAV，也不等待刮削。
- 影片海报墙进入多选后，点击「刮削选中影片」。选择可跨分页保留；全选按钮仅选择当前页，提交的是已选 ID。
- 影片详情顶栏的刮削图标：只处理当前逻辑影片。
- 演员管理「刮削前 1000 位演员」：按 WhatsAV 网站作品数量排名；人数允许 1～10000，默认 1000。默认只读取档案、头像和第一页附带的作品，完整作品分页可选。
- 任务窗口可暂停、继续、重试失败或缺失项、查看分页结果、核对字段覆盖、调整请求间隔及恢复被网站暂停的来源。关闭窗口或 Windows 不停止 NAS 任务。

资料随任务逐项入库。关闭任务窗口时会刷新对应列表；后台继续执行期间，可点击影片列表刷新或重新进入演员管理查看新资料。请求间隔调整从下一项任务生效。

## 数据与更新规则

影片、演员、厂商逐项写入幕境正式资料库；原始来源资料独立保留。已有图片进入幕境管理目录，Windows 和 Android 均沿用现有认证 API 读取。

默认任务复用已经完成的结果，补处理新影片及失败/缺失项；「强制重新获取来源资料」重新请求来源，仍保护人工修改。允许自动更新本采集器此前写入且用户未改动的字段。人工清空的字段也受到保护。产生覆盖冲突时，在任务结果中逐项确认，默认保留现有值；审核期间被再次编辑的字段拒绝覆盖，需重新采集核对。

演员优先按已经确认的来源 ID 映射复用幕境档案；首次跨来源关联时，以艺名、原名、译名、别名及已绑定的 MDCNG 来源姓名做唯一精确匹配。重名、归档档案或同站不同来源 ID 不会被自动合并，需要审核。制作商、厂牌、发行商分别保存角色，支持查看各自档案及关联影片、合作演员；不根据共同出演推断演员签约关系。厂商页面没有提供的成立时间、国家、Logo 或简介保持空白。网站自己的 Organization/Publisher 不导入为影片厂商。

影片有明确番号时按该番号采集，否则从文件名及直接父目录提取；无法识别、分集出现多个番号或文件与目录冲突时进入待核对，编辑影片番号后可重试。任务始终写回原影片 ID，不合并或改名源文件，不改动分集、播放历史或分类。

影片详情「来源资料」保留来源标题、导演、网站系列、标签、发行日期、网站上线日期和网站时长。这些字段不强行转换为现有三级标签或发行商所属系列；上线日期不当作发行日期，网站时长不覆盖文件探测时长。

MDCNG 的 NFO 和演员审核功能继续保留，作为可选导入；内置刮削不依赖 MDCNG 的挂载或数据库。

## MDCNG 演员资料与影片关联

推荐用 MDCNG 补充完整演员档案，用内置来源采集影片信息和出演名单。此功能读取已经完成的 MDCNG 演员任务与资料，不会代替 MDCNG 执行演员刮削。

- 先刮影片、后导入演员：MDCNG 的单条审核和批量导入都能识别唯一匹配的现有演员，复用其内部 ID、影片关联和 WhatsAV 来源映射。批量导入只补空白；已有姓名、生日、头像等需要在单条审核中确认后替换。
- 先导入演员、后刮影片：影片出演名单按来源映射或唯一姓名、别名匹配已有演员。MDCNG 已有字段与头像优先保留；WhatsAV 可补空白，但不会覆盖人工清空的字段，也不会补入与已有出生年月矛盾的生日。
- MDCNG 导入完成后，根据幕境已经保存的影片出演名单补关联。升级后首次启动也会对已有名单补关联一次，无需访问外站；归档演员、非活动影片和手动设置过的影片演员名单会被跳过。未刮过资料的影片需要先执行影片刮削，仅扫描文件不足以识别出演演员。
- 重名时，在 MDCNG 导入审核中选择目标演员，或在刮削任务的「核对」窗口中选择正确演员。后者保存稳定来源映射并继续原任务，暂停的任务仍保持暂停。未确认的身份不会被标记成已完成。
- 已经存在的两个独立演员档案不会被自动归并或删除，已确认的来源绑定也不会仅凭同名被迁移。普通演员 ZIP 资料包保持原有导入边界，不修改影片关系。

实机验收可选一部已刮影片，导入其演员的 MDCNG 资料，确认演员数量没有增加、详情资料得到补充且关联影片仍在；再从演员详情和影片详情分别核对同一关联。需要更新 NAS 和 Windows 管理端。

## 后台与恢复

### 先导 MDCNG，再补演员关联

分类管理新增独立按钮「补全演员关联（WhatsAV）」。该模式复用现有番号规则和 NAS 后台队列，处理当前分类的全部影片，重复执行会重新匹配；不依赖 Windows 已加载的页数。需同时更新 NAS 和 Windows，旧 NAS 未声明 `castSupplement` 支持时客户端禁止提交，避免被当成普通完整刮削。

- 只追加演员—影片关系。通过已有来源映射、艺名、原名、译名、别名及 MDCNG 来源名匹配；按用户要求，同名或别名对应多个未归档演员时全部关联，不自动归并档案。保留已有人工关联。
- 网站演员详情只用于读取姓名和别名，不下载头像，不新建演员，不修改演员档案，也不采集厂商和演员作品列表。没有匹配的出演名单持久保存并列为待核对；后续 MDCNG 导入会再次补关联，也可重试任务。核对中支持按需搜索 NAS 演员确认异名，稳定来源身份映射可供其他影片复用；只有名字的来源确认仅作用于当前影片。
- 影片字段仅允许补空简介；标题、番号、原名、海报、分类、标签、发行商、系列等不改。预览图为空或全部是有证据的封面时，补最多 20 张 WhatsAV 实际截图，保留原图并按内容去重。已有实际截图时不追加。新 MDCNG 导入会记录 fanart 封面来源；旧数据仅在导入审计时间与图片记录对应或图片内容等于海报时认定为封面，无法确认的旧图保留并跳过。截图下载失败时先保留下载缓存，重试整批成功后再写入画廊。
- 补关联任务不提供字段覆盖选项。原有完整刮削按钮保留其原行为，两种模式的任务去重键相互独立。

本地回归脚本：`dart run test/cast_supplement_test.dart`；真实网站和 NAS 测试由用户执行。

NAS 以单进程串行调度 Node 采集器，通过标准输入输出交换 JSON，不增加网络监听端口。浏览器异常不会停止影片播放服务；任务记录失败并按规则重试。

队列、任务范围、分页游标、来源身份、原始结果及字段来源保存在幕境 SQLite 中。暂停状态跨 NAS 重启保留；运行中被中断的任务恢复为待处理。重复提交同一工作共用任务，作品分页与派生演员/厂商任务也属于原批次。缺失或失败的图片可复用已获取文本重试。

`/data/scraper` 保存浏览器会话、请求节奏及可重建的下载/文本缓存。网站验证页会暂停来源，429 等待服务器冷却；手动恢复不会取消冷却。默认受控请求间隔 15～25 秒，范围 1～3600 秒；浏览器页面附属脚本和样式由浏览器正常加载。

应用备份包含正式 SQLite、影片海报、轮播图片、演员头像及厂商 Logo；浏览器 Cookie 和可重建缓存不导出。整目录迁移可在停止容器后复制 `/data`。正式清库由用户在正式部署阶段执行，本次没有清除现有资料。
