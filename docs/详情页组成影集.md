# 详情页组成影集

2026-10-15。功能已在 NAS、Windows 和 Android 平板管理模块实现；Android 手机普通详情页没有新增管理入口。改动尚未提交、部署到 NAS 或在真实影片库执行。

## 使用与数据规则

管理员在影片详情点击“组成影集”，搜索并选择同分类的其他影片，预览后确认。选择器使用服务端分页，每页 20 部，当前影片始终参与；一次选择 2–100 部，合计最多 500 个分集。支持跨硬盘、已有影集和离线影片，每部至少有一个分集。预览显示原影片、来源盘、路径和可用状态，支持调整分集顺序。

- 创建新的影集，将所有参与影片的全部分集转入其中；原影片隐藏，海报墙和分类统计只计算新影集。
- 主资料默认来自当前影片，可在确认页换成其他参与影片。译名、原名、番号、简介、海报、发行商、系列及扩展来源资料使用主资料；演员与标签按已有档案 ID 合并去重，不自动合并同名档案。
- 任一参与影片收藏，新影集即收藏；播放次数求和，源记录的已转移计数清零，避免重复累计。
- 截图按文件内容去重；缺失图片记录保留。直接转移保留的图片记录，重复图片留在隐藏源记录中，不复制或删除图片文件。
- 视频位置、分集 ID、分集标题保持；各集进度与观看历史转到新影集。成功后客户端打开新影集，并刷新海报墙与分类数量。
- 原影片资料保留；新详情“合并来源”展示原名称、原名与番号，包含此前合并的来源，最多展示 500 条。
- 合并后的资料标为人工来源，保护已确认的结果；重新扫描保持手工分集归属。

现有“拆分影集”使用影集当前资料，不能完整恢复每部原影片。此功能不提供一键撤销；确认页会说明这一点。

## 一致性与机械硬盘 I/O

预览读取参与记录及关系并生成快照摘要；提交时在磁盘工作队列内重新校验，再以一个 SQLite 事务创建目标、迁移分集/关系/历史并隐藏源记录。任意步骤失败整体回滚，包括资源版本；不会留下空目标或部分合并结果。相同快照但不同分集顺序的请求不共用队列结果。

参与影片存在未结束的采集/资料任务时拒绝合并；参与影片有播放或预览会话时，提交返回冲突。详情先停止自己的预览，其他设备需停止后重新预览。创建播放会话在异步解析文件后核对归属，进度/结束请求在读完请求体后再次核对会话与归属，防止迟到请求回写隐藏源记录。

截图先读取文件信息，只有大小相同的候选才顺序流式计算 SHA-256；按路径、大小、修改时间缓存摘要，最多 2048 项，避免切换主资料和提交时重复读取。数据库写事务中不读取图片，不读取视频内容，不移动媒体，不增加定时扫描、轮询或清理，也不降低 SQLite 耐久设置。实际机械盘寿命收益尚未量化。

## 管理员 API

两个接口都要求 admin，JSON 请求体最多 64KiB，拒绝未知字段。

`POST /api/v1/admin/collection-compositions/preview`

```json
{"movieIds":["current-id","other-id"],"metadataSourceMovieId":"current-id"}
```

响应 `200` 的 `data` 包含 `previewToken`、`metadataSourceMovieId`、主资料、`movies`、`episodes`、演员/标签并集、收藏及去重截图数。

`POST /api/v1/admin/collection-compositions`

```json
{
  "movieIds":["current-id","other-id"],
  "metadataSourceMovieId":"current-id",
  "previewToken":"预览返回的 64 位摘要",
  "episodeOrder":["episode-1","episode-2"]
}
```

分集顺序必须恰好包含全部参与分集各一次。成功 `201 {"data":{"movieId":"new-id"}}`；格式错误返回 400，以下业务冲突返回 409：

| code | 处理方式 |
| --- | --- |
| `collection_selection_changed` | 影片隐藏/删除、资料、关系或分集变化，重新预览 |
| `collection_category_mismatch` | 改为同一有效分类的影片 |
| `collection_episode_limit` | 排除空记录，限制到 500 个分集以内 |
| `collection_playback_active` | 停止参与影片的播放与预览，再预览 |
| `collection_task_active` | 等待相关采集/资料任务结束，再预览 |

客户端收到明确冲突后要求重新预览；提交期间禁止关闭与返回。超时/断线造成结果不确定时不允许直接重提，先关闭并刷新核对。已完成请求重复提交旧快照返回 409，不会再次创建影集。

影片详情增加可选 `compositionSources` 字段，旧客户端忽略即可；没有数据库 schema 迁移。先更新 NAS，再更新 PC/平板客户端，旧 NAS 不提供新路由。

## 验证

- NAS `collection_composition_api_test.dart` 使用临时 SQLite、文件与本地 HTTP：管理员权限、同分类跨盘、已有影集、离线、主资料切换、演员/标签/收藏、内容去重、顺序、活动任务与预览、并发编辑、重复提交、注入失败回滚、版本回滚、来源资料、进度/历史/次数、半个请求体的播放竞态、重扫归属与数据库完整性通过。
- NAS 另 10 个回归脚本通过：磁盘队列/I/O、跨盘影集、并发播放、观看历史、生命周期、批量标签、标签 API、标签转移、repository 边界及诊断日志。
- PC 完整 Flutter 测试 158 项通过，平板管理模块 169 项通过；新增界面回归覆盖 480/1024dp、键盘及大字体、主资料切换、排序、提交期间返回、冲突及结果不确定场景。真实本地 HTTP 测试验证请求、权限与错误码。
- 三个项目静态分析无问题；Windows debug 与 Android ARM64 debug 均构建成功。含影集功能的新包尚未安装，未做真实 NAS 机械盘压测或实体设备的影集合并验收。
