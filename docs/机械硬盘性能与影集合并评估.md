# 机械硬盘性能优化与详情页组成影集评估

日期：2026-10-14。检查基线：Windows `9d05f0f`、NAS `ee0d9d5`、Android `aea10be`。

本轮已修改 NAS、Windows 和 Android 平板代码；下述性能优化和功能同步已实现。本文保留 2026-10-14 的评估记录；2026-10-15 详情页“组成影集”已完成开发，现行行为、API 和验证以 [详情页组成影集](详情页组成影集.md) 为准。尚未部署 NAS 或操作真实影视库。此前批量优化的 Android 调试包已按要求安装到手机和平板，影集功能是之后新增的代码。

## 已实现的性能优化

| 操作 | 原行为 | 当前行为 |
| --- | --- | --- |
| 清空影片标签关联 | 客户端分页拉取影片，逐部读详情并 PATCH | 1 次管理员请求，NAS 在 1 个事务内批量清空活动影片关联 |
| 批量删除标签 | 客户端逐个 DELETE，多次独立数据库提交 | 1 次管理员请求，1 个事务，按三级、二级、一级用集合 SQL 删除 |
| 导入影片标签对照 | 客户端加载影片和标签，逐部读详情并 PATCH 全部标签 | 每 500 部 1 次请求、1 个事务；只查询匹配所需字段，预编译语句追加缺失关联 |
| 单部影片更新标签 | 删除所有标签关系再全部重建 | 在事务内计算差集，只删除移除项、插入新增项 |
| 单个标签删除 | 多条删除语句各自提交 | 相关删除语句统一在事务内提交 |
| 诊断文件日志 | 每条打开、追加并 flush | 250ms 或 64KiB 批次追加并 flush；ERROR 立即触发刷盘，正常停止等待日志刷盘 |

例如 1001 部影片的标签对照导入现在为 3 次请求，批次为 500/500/1。清空和批量删除的请求数不随影片、标签数量增长。数据库仍按已有耐久配置工作；日志仍按批次请求 flush，未关闭 SQLite 同步或外键检查。

这些改动减少 HTTP 往返、SQLite 提交、重复关系写入和日志文件操作，从而减少 `/data` 所在盘的写入及寻道压力。标签操作不读取、移动或复制视频，也不重新扫描媒体目录；临时候选表使用连接既有的内存临时表配置。减少 I/O 不等于可以推算机械盘寿命延长多少，实际收益还取决于 NAS 内存缓存、库规模、并发播放及其他服务。

普通诊断日志允许短暂缓冲，进程强制终止或断电可能丢失尚未刷盘的日志尾部；影片数据库的提交策略没有因此改变。ERROR 日志立即入刷盘队列，正常停服会等待队列完成。

### 保留的业务规则

- 清空关联覆盖所有 `lifecycle_state=active` 影片，包括来源暂时离线的影片；原本没有标签的记录不写入。受影响影片的标签字段设为人工来源，防止后续导入自动填回。合并后隐藏的源影片审计关联保留。
- 批量删除只处理未归档标签；仍被活动影片或子标签引用的标签保留并返回问题清单。归档标签保留。与原单标签删除一致，真正删除标签时会清理其隐藏源影片关联。
- 导入按忽略大小写、空白、短横线、下划线的番号匹配。找不到影片、出现多条同番号记录时不猜测；标签缺失时整部影片不写入。保留已有标签，只追加缺失项。
- 重复成功导入不会反复重写已有关系与已生效的人工来源标记。空标签映射不建立人工锁定。
- 数据库异常使当前批次整体回滚；每批事务独立，之前成功的批次保留。请求失败或超时后客户端停止，不自动重试，并列出尚未执行项。超时的当前批次结果需刷新核对，不能把未收到响应视为服务端肯定未提交。
- 运行期间关闭按钮与返回操作受保护；完成后才能退出。窄窗口按钮可换行。

### 新接口与升级顺序

所有接口继续要求管理员令牌。

| 方法与路径 | 请求 | 限制与结果 |
| --- | --- | --- |
| `POST /api/v1/admin/tag-management/cleanup` | `{"operation":"clearMovieLinks"}` 或 `{"operation":"deleteTags"}` | 请求体最多 1KiB；返回 `total/completed/skipped/failed/issues` |
| `POST /api/v1/admin/tag-management/movie-associations` | `format/version/films`，见下例 | 每批 1–500 部、请求体最多 2MiB；返回 `total/updated/unchanged/unmatched/ambiguous/failed/issues` |

```json
{
  "format": "mujing-adult-tag-enrichment-review",
  "version": 1,
  "films": [{"code": "ABF-001", "previewTags": ["示例标签"]}]
}
```

先更新 NAS，再更新 Windows 与 Android。旧 NAS 缺少批量路由时客户端会显示请求错误；不会自动退回逐条删除或逐部 PATCH。没有数据库 schema 迁移，也没有历史媒体文件搬迁。

### 同类路径检查与后续测量

现有磁盘工作队列、播放时后台读取预算、未变化扫描跳过视频探测与分集重写、事务回滚后的版本计数保护均保留，并已回归相关测试。本轮没有增加定期扫描、强制 VACUUM、后台清理或更激进的预读。

下一轮应在真实 NAS 测量空闲、批量标签操作、播放、扫描、MDCNG 导入的磁盘 IOPS、写入字节、操作耗时和 WAL 大小。播放进度存在续播与停播落盘要求，进一步节流应单独设计并覆盖暂停、结束、断线和重启；不能为了减少写盘丢失已确认的进度。

如果以后增加 SSD，优先把 `/data` 的数据库、WAL、日志和受管理图片放 SSD，视频仍保留 HDD。仅有 HDD 时本轮批量事务和去重写入仍生效；不要求改变部署硬件。其他容器或 NAS 系统服务造成的唤醒需要分别观测。

## 详情页“组成影集”的已确认规则（10 月 14 日评估记录）

以下保留当时的设计问题；对应功能现已实现，当前限制与验收见 [详情页组成影集](详情页组成影集.md)。

1. 当前影片与其他影片合并为影集分集，原影片从普通海报墙隐藏，沿用现有 `merged` 生命周期模型。
2. 第一版仅允许同分类，允许来自不同硬盘。
3. 默认沿用当前影片的标题、简介、海报等主资料；确认页可以选择另一部参与影片作为主资料来源。
4. 演员与标签取所有参与影片的并集并去重。
5. 视频留在原盘、原路径；只改变数据库中的分集归属。

### 必须先解决的问题

| 问题 | 现有实现与建议 |
| --- | --- |
| 合并原子性 | 现有 `mergeEpisodesIntoSeries` 要求目标已是影集，创建空影集是另一个操作。详情入口应一次事务完成建目标、迁移全部分集、资料合并、进度迁移和隐藏源记录，失败整体回滚。建议新建目标影集 ID，保留全部源记录供审计。 |
| 资料合并规则 | `_copyMovieMetadataToSeries` 当前替换演员和标签，不能满足并集要求。演员按档案 ID、标签按标签 ID 合并；标题、原名、简介、海报、发行商、系列取选择的主资料。原影片各自番号需保留审计或分集来源展示，不能把主影片番号当成所有分集的番号。 |
| 活跃播放会话 | 数据库会迁移历史与续播，但内存播放会话仍持有原 `movieId`，之后上报可能写回隐藏源记录。第一版建议有活动播放/预览的参与分集直接返回 409；另一方案是会话和所有写入都按分集当前归属重定位，需要更多回归。 |
| 并发修改 | 确认前后可能有扫描、刮削、MDCNG、改分类或另一管理员合并。应预览并携带参与记录版本，提交时重新校验；有变更返回冲突并刷新，不静默只合并部分。 |
| 整部影片与分集选择 | 详情入口建议按整部影片迁移全部分集，以保证原影片确实隐藏；若以后允许选择部分分集，剩余源影片必须继续展示。已有影集、没有分集的记录、离线分集需要明确支持范围与提示。 |
| 分集顺序与重名 | 跨盘可能重名，应展示原影片、来源盘和路径，默认稳定自然排序，并支持手动排序。保留 episode ID、各集路径与独立进度。 |
| 收藏、图片和来源审计 | 收藏建议任一源已收藏则目标收藏；截图建议去重保留来源并选主资料海报。人工字段保护、MDCNG/刮削导入审计和原资料应有明确归属，避免下一次导入覆盖人工组合结果。这些建议尚未作为新功能实现。 |
| 重扫后归属 | 扫描已有保持分集归属的逻辑，新入口仍需用“手工跨盘合并后重复扫描”用例验证，不因目录结构把影集拆回。 |
| 撤销与拆分 | 现有拆分会复制影集当前资料，并不等同于恢复各原影片。若要提供“撤销本次合并”，需保存原归属、顺序和资料快照，不能承诺现有拆分可完整还原。 |
| 两端刷新 | 新接口返回目标 movieId；成功后进入影集详情，刷新海报墙、分类数量、演员/标签结果和相关详情缓存。Windows 与平板应同一轮实现和验收。 |

### 建议实现顺序

先增加 NAS 原子合并与冲突检查，再提供详情页同分类影片搜索和确认页。选择器使用服务端分页搜索，默认选中当前影片，显示来源盘和分集数，避免预加载全库或逐部拉详情。确认页展示参与影片、主资料来源、合并后的演员/标签和分集顺序。

测试至少覆盖跨盘同分类成功、跨分类拒绝、主资料切换与关系并集、失败整体回滚、进度和历史保留、活动会话冲突、并发编辑冲突、离线分集、重复扫描保持归属，以及 Windows/平板成功后刷新和跳转。新接口及两个入口在本轮尚未编写。
